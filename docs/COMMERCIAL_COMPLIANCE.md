# Commercial Compliance Report

This document tracks whether StratoSort Stack is ready for commercial distribution.

## Current Decision

- Decision: **Go (subject to per-platform binary completion and ongoing license-attribution
  upkeep)**
- Date: **2026-09-14**
- Reason: The repository license is PolyForm Noncommercial 1.0.0 for personal/noncommercial use;
  commercial rights are sold separately. All bundled npm dependencies and model artifacts that
  remain in the catalog have explicit, commercially-compatible licenses or are covered by a
  documented attribution obligation surfaced in the installer (`THIRD_PARTY_NOTICES.md` shipped as
  `extraResources`).

## Scope Covered

- npm dependencies (direct + transitive) via `package-lock.json`
- Runtime and packaging configuration via `electron-builder.json`
- Downloaded model artifacts in `src/shared/modelRegistry.js`
- Bundled runtime binaries (llama-server, FFmpeg, and on Windows the Microsoft Visual C++
  Redistributable) shipped under `assets/runtime/`
- Asset and documentation licensing consistency

## Per-Platform Bundling Status

| Component                        | Windows                   | macOS                       | Linux                     |
| -------------------------------- | ------------------------- | --------------------------- | ------------------------- |
| All npm deps + native modules    | bundled                   | bundled                     | bundled                   |
| Vision runtime (`llama-server`)  | bundled                   | bundled                     | bundled                   |
| Tesseract.js WASM + lang data    | bundled                   | bundled                     | bundled                   |
| FFmpeg (LGPL)                    | bundled                   | bundled (self-hosted build) | bundled (BtbN static)     |
| Microsoft VC++ Redistributable   | bundled (see note below)  | not applicable              | not applicable            |
| LLM/embedding/vision GGUF models | user-fetched at first run | user-fetched at first run   | user-fetched at first run |

End-user post-install setup is limited to selecting and downloading model files. No other manual
installation steps are required. Linux x64/arm64 dist builds bundle a static LGPL FFmpeg (BtbN);
Windows arm64 ships without a bundled FFmpeg (no upstream LGPL build) and falls back to a system
`ffmpeg` on `PATH`. The PATH fallback also applies when `SKIP_FFMPEG_RUNTIME=true`.

### Microsoft Visual C++ Redistributable (Windows)

Windows packages bundle Microsoft's unmodified `vc_redist.x64.exe` / `vc_redist.arm64.exe` (v14, the
latest supported 2015-2022+ runtime, from `https://aka.ms/vc14/…`), which the installer and the
in-app **Install now** action run when `msvcp140.dll` / `vcruntime140.dll` are missing.
`scripts/setup-vc-redist.js` keeps the file only when its Authenticode signature is Valid and from
O=Microsoft Corporation; `win.signExts` in `electron-builder.json` keeps our signing step from
re-signing it; `scripts/verify-packaged-artifacts.js` checks the packaged copy's sha256 (and, on a
Windows host, its Microsoft signature). The redistributable is Microsoft **Distributable Code**
under the Microsoft Visual Studio license terms, not an npm dependency, so the inventory in
`docs/commercial-use-inventory.json` does not list it.

- **Personal / noncommercial builds:** fine to ship as is.
- **Business / commercially licensed builds:** before shipping, the distributor must confirm it
  holds a Visual Studio license whose terms cover redistribution of the Distributable Code (and meet
  those terms, e.g. distributing it unmodified and only as part of the application). If that cannot
  be confirmed, build without it (drop the `win.extraResources` entry): the installer and the app
  then fall back to opening Microsoft's download page.

## Required Ongoing Discipline

1. Keep `THIRD_PARTY_NOTICES.md` in sync with bundled binaries and dependencies.
2. Keep `assets/runtime/ffmpeg/NOTICE.md` source-offer link pointing at the exact build SHA in use.
3. Run `npm run compliance:commercial:verify` before each release; the CI gate (`npm run ci`)
   already enforces it.
4. Re-evaluate model catalog additions through `commercial-model-licenses.json` before exposing them
   to users.
5. Monitor Llama 3.2 Additional Commercial Terms (700M MAU threshold) — not a current concern at our
   scale.
6. For a business/commercially licensed Windows build, confirm the Visual Studio redistribution
   license for the bundled Visual C++ Redistributable before shipping (see above).

## Appendix A: Pre-Release License Audit Process

Before each major release, verify production dependency licenses remain compatible with the intended
distribution model.

### Regenerate the report

```bash
npm run licenses:production
```

Review the JSON for **GPL**, **AGPL**, **SSPL**, or other strong copyleft terms that may conflict
with a commercially licensed distribution of this app. Native addons (`sharp`, `better-sqlite3`,
`node-llama-cpp`, `@napi-rs/canvas`, `lz4-napi`) often pull MIT/BSD/Apache-style licenses; still
confirm transitive packages.

For complete commercial-readiness status (dependencies + models + binaries + waivers), use:

```bash
npm run compliance:commercial:build
npm run compliance:commercial:verify
```

`docs/licenses-production.json` is **gitignored**. It is derived from `package-lock.json` through
the same inventory as the compliance gate: every package that is not `dev: true`, plus the
`BUNDLED_RENDERER_DEPS` closure (`scripts/compliance/commercial-compliance-lib.js`) that webpack
compiles into the renderer bundle despite living in `devDependencies`. Generate it locally or in CI
before each release and review for new copyleft entries. `npm run audit:bundled` (part of
`npm run ci`) applies the same closure to `npm audit`, which `--omit=dev` would otherwise skip.

### Standing notes from the 2026-05 review

- **Project license:** Root `LICENSE` is PolyForm Noncommercial 1.0.0. Commercial rights are sold
  separately (`docs/COMMERCIAL.md`). Third-party obligations attach to the components inventoried in
  `THIRD_PARTY_NOTICES.md`.
- **`sharp` / `@img/sharp-*`:** Reported as `Apache-2.0 AND LGPL-3.0-or-later`. LGPL-3.0 obligations
  (license text + written offer of source for libvips) are satisfied by `THIRD_PARTY_NOTICES.md`,
  which ships with the installer via `extraResources` in `electron-builder.json`.
- **`jszip`:** `(MIT OR GPL-3.0-or-later)` — dual license; we elect the MIT path. Recorded in
  `THIRD_PARTY_NOTICES.md`.
- **Unknown-license transitive entries:** None as of 2026-10-27. If one appears, verify its license
  upstream and record a waiver in `docs/commercial-compliance-waivers.json` (with a follow-up to
  remove it once the upstream SPDX metadata is fixed); the file's own notes describe the
  requirements.
- **Bundled FFmpeg:** LGPL-3.0 binary on Windows (x64), macOS (x64/arm64), and Linux (x64/arm64);
  Windows arm64 relies on a system `ffmpeg` on `PATH`. Attribution and source-offer live in
  `assets/runtime/ffmpeg/NOTICE.md`, also shipped via `extraResources`.
